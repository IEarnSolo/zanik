## What happened

Steam restored its official `RSDragonwildsServer-Linux-Shipping` file over the
Zanik preload launcher. Dragonwilds started without `LD_PRELOAD`, so the mod's
HTTP listener never started and the website was unavailable. After restoring
the launcher, the exact-hash guard correctly disabled kill tracking for the
unknown executable instead of patching an unverified address.

## What remained compatible

The player database, known players, saved skills, historical kill totals,
database schema, pages, API formats, player discovery, skill reading, kill
attribution, duplicate suppression, and persistence logic were unchanged.
Historical information remained intact throughout the update.

## Applied repair and verification

The new official executable was preserved as `.zanik-original`, the preload
launcher was restored, and the native addresses and exact executable hash were
updated. Static analysis confirmed the exact `OnAIKilled` signature, unchanged
arguments, its call from `ADominionAICharacter::OnDeath`, and one unique hook
prologue. Linux unit and HTTP tests passed, the API returned successfully, and
live enemy kills were subsequently confirmed by the server owner.
